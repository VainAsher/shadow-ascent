# Telemetry Targets Index

## Checklist
- [ ] Keep telemetry tied to actual design questions, not curiosity
- [ ] Separate required internal signals from nice-to-have metrics
- [ ] Review whether each metric helps with clarity, fairness, pacing, or stability
- [ ] Record any telemetry choice that creates implementation, privacy, or storage cost

## Drift Risks
- Telemetry sprawl can create busywork without better decisions
- Overreacting to discomfort metrics can sand off intentional emotional pacing
