# Review and Approval

## Approval Rule
For this GDD, approval means "this wording is good enough to guide future implementation and future revisions." It does not mean "perfect forever."

## Review Roles
- **Owner review**: the project owner decides whether a design direction is accepted into canon.
- **Evidence review**: when a topic claims repo-backed truth, the wording should be checked against current implementation or current canonical docs.
- **Design review**: when a topic goes beyond implementation and defines future intent, it should be checked for internal consistency with the rest of the GDD.

## What Needs Review
At minimum, review should happen when a change affects:
- plot or emotional spine
- character function
- movement meaning
- difficulty or pacing philosophy
- audience or product framing
- world structure

## Evidence Rule
If a section claims something is already true, it should point to:
- the live repo
- current canonical docs
- authored data contracts

If it cannot, it should be framed as direction, not fact.
