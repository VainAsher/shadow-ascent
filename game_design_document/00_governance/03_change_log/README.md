# Change Log

## Purpose
The change log records meaningful design movement over time so the GDD has memory. It should answer "what changed?" and "when did it change?" without forcing someone to diff the whole tree manually.

## What Counts As A Meaningful Change
- new or revised story spine
- major character reinterpretation
- movement meaning changes
- difficulty or pacing philosophy changes
- audience or product positioning changes
- world structure or ending changes

## What Does Not Need A Change Log Entry
- typo fixes
- sentence smoothing that does not alter meaning
- formatting cleanup
- navigation-only index updates

## Relationship To Decision Log
Use the change log for chronological tracking.
Use the decision log for reasoning when a change needs justification.
