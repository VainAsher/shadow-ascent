# Governance

## Purpose
Defines how the GDD is maintained, reviewed, updated, and connected to implementation.

## Governance Rule
This folder exists so the GDD behaves like a living product document rather than a one-time writing exercise. The design content elsewhere in the tree should be readable on its own, but governance defines:
- how truth changes
- who approves those changes
- where rationale is recorded
- how implementation and design stay connected

## What Belongs Here
- lifecycle rules for topic status
- review and approval expectations
- change history for meaningful design shifts
- decision records for important direction changes
- contributor workflow for future updates

## What Does Not Belong Here
- detailed game design content that belongs in a domain folder
- implementation notes that should live in engineering docs unless they affect design truth
- speculative brainstorming that has not been accepted into the GDD
