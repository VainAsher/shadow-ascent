# Contribution Workflow

## Workflow Rule
GDD edits should be treated like product changes, not private note-taking. A contributor should be able to explain:
- why this topic changed
- whether the change reflects current truth or new direction
- what other sections may now need revision

## Recommended Flow
1. Identify the topic being updated.
2. Check whether the change is factual alignment or design change.
3. Update the topic `README.md`.
4. Update the topic `INDEX.md` if the checklist or status meaning changed.
5. Add a change-log or decision-log entry when appropriate.
6. Recheck related domains for contradiction.

## Cross-Section Rule
Do not update a character, region, or mechanic in isolation if the same change obviously affects:
- plot progression
- world structure
- difficulty philosophy
- interface communication

## Documentation Honesty Rule
If the GDD is ahead of implementation, say so.
If implementation is ahead of the GDD, bring the GDD forward.
If the truth is unclear, do not fake certainty.
