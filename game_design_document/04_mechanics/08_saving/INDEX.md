# Saving Index

## Checklist
- [ ] Define save triggers, checkpoints, autosave boundaries, and failure recovery expectations
- [ ] Clarify what data persists across death, quit, and version changes
- [ ] Link saving behavior to Beacon, shrine, and hub logic where relevant
- [ ] Record any risk to narrative sequencing or soft-lock recovery

## Drift Risks
- Weak persistence rules can break trust in a progression-heavy exploration game
- Overly permissive saving may flatten tension if it bypasses authored risk and recovery loops
